# Relief Ops: Disaster Response Logistics

Hazard-aware relief fleet routing on the real OpenStreetMap road network of Hyderabad. This is the
working system behind the DAA PBL report *Disaster Response Logistics: Multi-Depot Routing and
Resource Allocation with MST Backbones, Greedy Prioritisation and Dynamic Programming* (Group 16:
Bulla Joel Arpith, Joe Daniel, Macha Saikamal, Jayanth). The interface is built on the Thermal Watch
console design system (glass panels, MapLibre, React Bits).

It has two views over one shared backend:

| View | URL | What it does |
|---|---|---|
| **Dispatch console** | `#/admin` | Every vehicle on the map, coloured by risk, with what it will run into. Report a flood, fire, collapse, landslide, cyclone or chemical hazard by clicking the map, and the affected drivers are alerted. You can reroute one driver, re-plan the whole fleet, see the Kruskal clearance plan, and message drivers. |
| **Driver app** | `#/driver/<id>` | Built for phones. Shows deliveries in deadline order and raises an alert (banner, vibration, sound, system notification) when a hazard lands on the route. A safer route is computed automatically when the road ahead is closed, and one tap accepts it. The driver can acknowledge hazards and reply to dispatch. |

## The report's pipeline, running live

`src/lib/algo.ts` ports `logistics/graph.py` and `logistics/plan.py` from the report to TypeScript
and runs it on the OSM graph (9,196 intersections, 12,195 road segments) instead of a random one.

| Stage | Algorithm | Where it shows up |
|---|---|---|
| Road clearing | Kruskal MST + union–find, weight = clearing effort | *Clearance plan* layer: the fewest crew-hours that reconnect the network |
| Travel times | Dijkstra with a binary heap on passable roads | every route, ETA and reroute |
| Allocation | greedy: critical first, earliest deadline, nearest depot with stock | *Re-plan* |
| Loading | 0/1 knapsack DP, value = units × priority | each vehicle's load |
| Routing | subset DP (Held–Karp with deadlines), nearest neighbour above 13 stops | stop order on plan and on reroute |
| Live risk | per-driver walk of the remaining route against each hazard | the risk colours, alerts and KPIs |

Hazards change the road graph directly. Severity 1 slows roads to 2.5× travel time, and severity 2–3
closes them. A forecast hazard (one that starts in the future) does not slow anyone yet, but every
reroute already avoids it.

On a reroute, a driver already on the road keeps the stretch driven so far, and the remaining stops
are re-solved from the next intersection. On-time stops are chosen by the subset DP, as in the
report. Unlike the report's planner, stops that can now only be reached late are still delivered,
after the on-time ones. Only unreachable stops are dropped, and dispatch sees them.

`npm run check` reproduces the report's worked examples and runs these tests:

- the 3-stop DP (value 11, route 0→1→2→3)
- the nearest-neighbour counterexample (1 vs 11)
- knapsack against brute force
- on the real graph, that a flood closes roads, that Kruskal reconnects them, and that a reroute
  never crosses a closed road

## Architecture

```
public/graph.json          OSM road graph (scripts/build_graph.py from an Overpass extract)
src/lib/algo.ts            the six stages + live assessment + reroute (no dependencies)
src/lib/places.ts          depots, hospitals/camps/shelters, seed hazards, drivers
src/lib/ops.ts             shared store: graph, polled backend state, derived risk, Open-Meteo rain
src/components/OpsMap.tsx  MapLibre map: hazards, closures, routes, vehicles, clearance plan
src/views/AdminView.tsx    dispatch console
src/views/DriverView.tsx   driver app
functions/api/[[route]].ts Cloudflare Pages Function over D1: hazards, trips, acks, messages
functions/seed.json        initial dispatch, generated by scripts/seed.ts with the same pipeline
```

Routing runs in the browser, so the backend only validates and stores. Both views poll
`GET /api/state` every 3–4 s. Vehicle positions are derived from each trip's dispatch time, so
every viewer sees the same vehicle in the same place.

| Endpoint | |
|---|---|
| `GET /api/state` | hazards, drivers with trips and acks, last 80 messages |
| `POST /api/hazards` | `{kind, lat, lon, radius_m, severity, starts_in?, note}` |
| `DELETE /api/hazards/:id` | mark a hazard cleared |
| `PUT /api/drivers/:id` | `{path, stops, restart?}` new trip (reroute keeps the clock) |
| `POST /api/drivers/:id/ack` | `{hazard_ids}` |
| `POST /api/messages` | `{driver_id, sender, text}` |
| `POST /api/reset` | restore the seeded scenario |

The schema creates itself and seeds on first request, so there are no migrations to run.

## Running it

```bash
npm install
npm run build
npx wrangler pages dev dist      # UI + API + local D1 on http://localhost:8788
```

For UI work with hot reload, run `npm run dev` (port 3000, proxies `/api` to 8788) next to the
command above.

Deploy (Cloudflare Pages + D1; `wrangler.toml` holds the binding):

```bash
npm run deploy
```

Rebuild the graph or the seed:

```bash
python3 scripts/build_graph.py scripts/osm_raw.json public/graph.json   # osm_raw.json from Overpass, see the script
npm run seed
```

## Honest limits

- **Simulated GPS.** Vehicles move along their route at 6× real time (a 60-minute trip plays in
  10 minutes), and the demo loops. Real vehicles would post `navigator.geolocation` instead.
- **No authentication.** Anyone with the link can act as dispatch or as any driver. The API
  validates inputs and caps the hazard count, but this is a demo deployment.
- **One-way streets are ignored.** The graph is undirected, as in the report. Relief convoys often
  run under escort, but a production router would respect `oneway`.
- **Synthetic demand.** Places are real Hyderabad locations. Demand, stock, deadlines and the seeded
  hazards are synthetic, shaped like the October 2020 Musi / Gurram Cheruvu floods.
- **Robust policy not live.** The report's Monte Carlo robust policy (planning on 90th-percentile
  travel times) is not wired into the live system. Here, uncertainty comes in as forecast hazards.
